# ha-notice: implementation plan

Implements [interface.md](interface.md) and [design.md](design.md). The issues for each stage are expanded into bite-sized test-first steps when they are picked up; this plan fixes the order, the conventions and the module map.

## Conventions for every stage

- **Gateway boundary.** All HTTP and clock access goes through `src/ha_notice/gateway.py`; modules never import `http.client`, `urllib` or `time` directly (the gateway uses `http.client`; `urllib` is not used at all). Tests substitute fakes.
- **Fakes.** A fake Home Assistant server in `tests/` returns each row of the interface's Home Assistant edge table, serves `GET /api/`, and can delay, stall name resolution, trickle a response, drop after the request, redirect or answer 200 with a wrong body. It serves HTTPS with a self-signed certificate (to test `details.tls` and `ca_file`) and plain HTTP with `allow_insecure_http` for the rest. There are no sibling tools to pin.
- **Process and live split.** Process tests call `cli.main(argv, env, gateway)` in-process with a fake gateway (name resolution, monotonic clock, home directory and uid, input reading, state-directory hooks where a test needs a hostile path, CA path candidates, the connection script); no test-only environment seam is allowed. A small set of real-socket tests stays: a local HTTPS server with a self-signed certificate and `ca_file`, and a plain-HTTP server with `allow_insecure_http`. `live` tests (pytest marker, never in CI) send marked notifications to the maintainer's own service and need a person to look at the phone; they are listed in the live-verification issue.
- **Golden files.** `--json` outputs, request bodies and log records have golden files; schemas have positive and negative samples.
- **Spike regressions.** Every behavior in design.md's live-verification table becomes a fake-server test or a `live` test.
- **Secrets.** A test sets a recognizable fake token and asserts it appears in no argv, URL, output, log or error, and is sent to no host other than the base URL's.
- **Config and state (Stage 1 and 2 additions).** `HOME` and `XDG_CONFIG_HOME` set to a directory with a hostile config are not read, `HOME` unset still works, a failed password-database lookup (`KeyError`), an empty, relative or missing home each exit 2 `config_invalid` with `details.key` `home` before anything is read or sent (the actor user is `unknown`), `--config` plus drop-ins in its directory; a strict-loader table (`enabled: no`, `off`, `yes`, `010`, `timeout: 1:30`, `0x10`, `1_0`, `.inf`, `.nan` are `config_invalid`; a duplicate YAML key is `config_invalid`; a config path that is a FIFO returns at once (opened with `O_NONBLOCK`, not a regular file); a `RecursionError` and any parser error are `config_invalid` with no snippet echoed; `enabled: true`, `timeout: 10`, `timeout: 1.5` accepted); `[` repeated 1000 times and a 413-byte alias bomb (`config_invalid` or fast, no hang); a YAML error that would quote a fake secret (absent from stdout, stderr and the envelope); an unknown key of 5000 characters (`details.key "?"`); `level_prefix: "A\nB"` and two spaces refused; `timeout: 2s` alone loads; `base_url: ftp://x` with `--dry-run` exits 2 at step 2; missing `service` with `--dry-run` exits 0; missing `base_url` exits 2 before stdin is read, and so does an unreadable `ca_file`; a token with an interior space, with a trailing CRLF (trimmed) and of 4097 characters; `default_group: " "` and `"a b"` refused; `config.example.yaml` validates against `schemas/config.json` and loads with the stated defaults.
- **`make verify`** passes before every commit; each paragraph in markdown is one line.

## Module map

| Module | Stage | Responsibility |
|---|---|---|
| `gateway.py` | 0 | HTTP, clock, name resolution, `home_dir()` and `uid()`, `read_source`, state-directory access. |
| `cli.py` | 0, 3, 4 | Parsing, dispatch, exit codes, output. |
| `output.py` | 0 | Output sink, exit-code table, error envelope and human lines. |
| `payload.py` | 1 | Input parsing, validation, sanitizer, command keywords. |
| `render.py` | 1 | Request body and `data` allowlist. |
| `config.py` | 1 | Config from the password-database home, drop-ins, strict YAML, no environment overrides. |
| `state.py` | 2 | Safe state directory and file opens; one fixed warning. |
| `log.py` | 2 | Log records and rotation. |
| `hass.py` | 3, 4 | URL building, request building, one attempt, the probe call. |
| `retry.py` | 3 | Retry loop (429, connect-phase), waits. |
| `response.py` | 3 | Pure mapping of an answer or an exception (with the gate state) to a success or an error spec. |
| `link.py` | 1 | The link rule (syntax, scheme, port, IPv6 literal). |
| `send.py` | 3 | The `send` pipeline: config, input, validation, render, dry-run, delivery. |
| `deadline.py` | 3 | The whole-send deadline: gate, worker thread, decision at the deadline. |
| `signals.py` | 3 | The signal flag and its checkpoints. |
| `validate.py` | 4 | The `validate` command: config, credential, probe and test-message checks. |

## Stage 0: Scaffold and gateway

**Goal**: A package that installs, prints `--version`, and has the gateway and the fake server in place.
**Success Criteria**: `make verify` green; schemas load; the fake server serves each response row.
**Tests**: version output golden; fake server contract tests; schema positive and negative samples.
**Status**: Complete

## Stage 1: Config, input, sanitizer, command keywords and rendering

**Goal**: Load and validate config, then validate and render a notification without any network.
**Success Criteria**: invalid config exits 2 naming the key; `send --dry-run` prints the exact request body for stdin, file and flag input, with the `data` allowlist, tag, link and truncation applied, and needs neither `base_url`, `service` nor the token.
**Tests**: config table (`base_url` fuzz: percent-encoded host, `host:abc`, `host:99999`, backslash, non-ASCII, `//` in the prefix; the userinfo, query, trailing slash, path prefix and `http` without `allow_insecure_http` cases; stdin that sends 10 bytes and stalls exits 12 `unavailable` (`details.phase` `input`, retryable true, `unknown_outcome` false) at the deadline with no hang, and logs `failed`; an `OverflowError` and a `RecursionError` from the JSON parse exit 20 `invalid_payload` with pointer `""`; `--stdin-json` on a pseudo-terminal exits 2; `<&-` closed stdin; a 5000-digit integer; `{"message":"a","<5000-char key>":1}` gives pointer `/?`; `--stdin-json --file x --dedupe-key=...` with `enabled: false` exits 2, not 22; a regular file larger than the cap; SIGTERM, SIGINT and SIGHUP during input exit 128+N with no envelope, no request and no log record; empty stdin, `[]`, `null`, `"x"`, BOM, duplicate keys, `NaN`, 100000-deep nesting, 1 MiB + 1 bytes, FIFO as `--file`, `--file /dev/zero`, a directory, a symlink to a regular file accepted); ## Stage 2: State directory and log

**Goal**: The safe state directory and the log, with state problems never failing a send.
**Success Criteria**: log records match the schema and never contain text, URL, service or token; an unusable state directory leaves the exit code unchanged and prints one warning.
**Tests**: unusable directory tests (symlinked directory, mode 0755, read-only, wrong owner, a path where `os.open` raises); a FIFO named `log.jsonl` and `log.lock` (send returns at once, one warning, exit code unchanged); a `flock` held by another process (record skipped after about 1 s, exit code unchanged); a symlinked `log.lock`; rotation reopen (the record lands in the new `log.jsonl`, not `.1`); concurrent rotation with two processes; `HOME` and `XDG_STATE_HOME` ignored; `ts` in UTC with milliseconds; log golden files and rotation; the outcome rule (`outcome_unknown` whenever `unknown_outcome` is true, exit 12 or exit 1; `unavailable` is `failed`); an exit 1 after the gate reached `writing` is logged as `outcome_unknown` with code `internal`, an exit 1 before is not logged, a signal exit 128+N is not logged; the result is on stdout before the log step starts (a log lock held by another process delays only the log, and the whole run ends within `timeout` plus 3 s).
**Status**: Complete

## Stage 3: Send

**Goal**: A real `send` against the fake server with the full response table and the deadline.
**Success Criteria**: every row of the Home Assistant edge table maps to its exit code and envelope; the token is sent only as the header to the base URL's host; a double or trailing slash never reaches the host; the whole run finishes within `timeout` plus 3 s (callers kill no earlier than `timeout` plus 10 s).
**Tests**: response table including the opaque 400 hint; every status 100..199 and every status outside 100..599 as `wrong_host_response` with `unknown_outcome` true and `details` null (schema-valid); the wrong_host_response schema samples (null details valid only with `unknown_outcome` true, `{}` or a foreign shape invalid); 429 x3 with any `Retry-After` header (`nan`, `-5`, `1e999`, an HTTP date, `5`, `45`, `0`, `²`) ignored and waits staying 2 s and 4 s; 429 twice then connection refused (the retry counters are independent; four requests at most); a table test per exception class in both phases, set by the gate state alone (`ConnectionResetError`, `BrokenPipeError`, `TimeoutError`, `ssl.SSLEOFError`, `RemoteDisconnected`, `BadStatusLine`, `LineTooLong`, `IncompleteRead`, `InvalidURL`: gate idle `network_error`, gate writing `outcome_unknown` or `wrong_host_response`, never retried; an exception from the first `conn.request` call is `outcome_unknown` whatever bytes were written); a 429 then a deadline during the 2 s wait or the retry connect (gate returned to idle: `network_error` retryable true, `unknown_outcome` false, not `outcome_unknown`), a 429 then a connection failure on the retry connect (retried once), every attempt after an abandoned gate refuses to write, and a response that completes at the deadline (the result slot wins, exit follows the response); the gate lock is never held across a socket call; an uncaught worker exception prints nothing and exits 1 with the fixed message `internal error` (no class name); a fake gateway that blocks connect past the deadline and then proceeds (assert `network_error` was reported, zero request bytes written, exit 12) and one that blocks after the first byte (`outcome_unknown`); a `daemon=True` assertion; CA fallback cases (compiled cafile exists but is empty, capath is an empty directory, both missing; `ca_file` alone is the whole trust when the default trust is empty and is added when it is not; a capath directory of unhashed files gives `network_error` with `tls` true, not retryable); envelope tests per cell of the exit-12 table with and without `--dedupe-key`, a hostile pointer as a key (`details.pointer "/?"`) and an unknown config key (`details.key "?"`); connect-refused retried once; a 5xx not retried; drop after the first byte gives `outcome_unknown` with no retry and `retryable` true only with a tag; a stalled name resolution, a stall after the first byte and a byte-by-byte response (total wall time under `timeout` plus 3 s); a SIGTERM during the send (stop path, result by gate state) and before the send (exit 143, no envelope); TLS failure and `ca_file`; a fake proxy and a fake CA in `SSL_CERT_FILE` (zero connections reach the proxy, the fake CA does not verify); redirect not followed (a second server gets zero requests); an injected `InvalidURL` or `ValueError` carrying a fake secret (absent from stdout, stderr and the log); a token with CR LF and with non-Latin-1 characters; the token leak test; `enabled: false` exits 22; the insecure-http warning; the parser table (`--conf` and `--stdin` rejected, `--config=x` and `--dedupe-key=-abc` accepted, `--dedupe-key -abc` exits 2, `--config x send` and `send --config y` both honoured); closed stdout (`>&-`) and a pipe closed early after a delivered send leave the exit code unchanged; a non-UTF-8 locale (`LC_ALL=C`) with a non-ASCII dedupe key; the human-line table.
**Status**: Complete

## Stage 4: `validate`, live verification and docs

**Goal**: `validate [--probe] [--test-message]`, the live suite and user documentation.
**Success Criteria**: probe (a 200 JSON object is ok, every other result fails with exit 12) distinguishes a bad token and an unreachable host; the live suite settles the still-to-verify items; README documents token creation, the service name and cron use.
**Tests**: validate golden files with the check names `config`, `credential`, `probe`, `test_message`; probe against the fake server (`GET /api/` only); `validate` never prompts; plain `validate` with `enabled: false` exits 0 with `enabled: false`, and exits 12 with a broken credential; with `--test-message` or `--probe` it exits 22 with no call and before any check, even with an unset credential; `validate --dry-run --test-message` still sends; probe with a 200 `[]` (fails, `api_ok` false), a 200 `{}` (ok), 401, 404, a stalled host and a retry on 429; command-keyword rows: NUL then the word (sanitized first, then refused) and `update_` (empty tail) refused; live tests (plain, tag replacement, link tap, a long message, the Android markup look of V20, the `GET /api/` response, an unreachable-host timeout).
**Status**: Complete

## Version roadmap

- **0.x**: Stages 0 to 4.
- **1.0** when the live suite has passed and the tool has run in daily use through a routing tool for two weeks without an interface change.
- **1.x, additive**: per-level `data` keys (`importance`, `channel`, `ttl`, `priority`, `push`) after a live phone test, `--service` or `--group` flags if a router needs them, notification actions with allowlisted URI schemes, notification replacement and clearing by tag (`clear_notification` through a dedicated command, never through `message`), non-companion notify services.
- **2.0**: nothing planned.
